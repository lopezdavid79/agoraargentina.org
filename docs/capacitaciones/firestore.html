1. Jerarquía de Colecciones

Firestore
└── capacitaciones/{slug}                        ← documento de capacitación (ID = slug)
    └── modulos/{autoId}                         ← subcolección de módulos (ID autogenerado)
  • La capacitación se escribe con db.collection('capacitaciones').doc(finalSlug).set({...}) — el ID del documento es el slug normalizado (controller/adminController.js:343).
  • El módulo se agrega con db.collection('capacitaciones').doc(idCap).collection('modulos').add({...}) — ID autogenerado por Firestore (controller/adminController.js:483).
  • La subcolección se lee ordenada por orden ascendente (controller/mainController.js:173-175) y en el gestor admin (controller/adminController.js:460).

6. Notas de Comportamiento

  1. Default de alta: una capacitación nueva se escribe con estado: "borrador" (controller/adminController.js:353) y fecha: new Date() (:352), con creadoPor tomado de la sesión (:354) y categoria con default "General" (:347).
  2. Delta de edición: updateCapacitacion agrega fechaActualizacion: new Date() (controller/adminController.js:423) y no toca el slug (es el ID del documento); el bloque de alta (:343-355) no contiene fechaActualizacion.
  3. Filtro público: el listado público exige estado == "Activo" (controller/mainController.js:146) y el detalle devuelve 403 si estado !== "Activo" (:169-171).
  4. Tope de grabaciones: parseGrabaciones limita a 10 elementos (controller/adminController.js:20), descarta entradas sin URL y ante JSON inválido devuelve [] (:9-22).
  5. activo en módulos: storeModulo lo fija en true (controller/adminController.js:492); updateModulo lo define con activo === "on" ? true : false (:569).
  6. Visibilidad en detalle público: solo se muestran módulos con activo === true (controller/mainController.js:179).
  7. Fallback legacy: si grabaciones está vacío, la vista usa claseGrabada como única grabación (views/capacitaciones/detail.ejs:70); la edición precarga el mismo fallback y etiqueta los strings como "Clase Grabada N" (views/admin/capacitaciones/editModulo.ejs:87-91).
  8. Normalización de privado: el valor booleano se deriva con (privado === 'on' || privado === 'true') tanto en alta (controller/adminController.js:349) como en edición (:419).
